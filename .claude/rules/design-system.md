# Design system

`packages/design-system` is the single source of truth for the aiBytes_ **app
and Chrome extension**. The newsletter is not a consumer — see the newsletter
rule for why.

- `tokens/tokens.json` is authored. `dist/` is generated by
  `npm run build:tokens`; never edit `dist/tokens.css` or `dist/tokens.js`.
- Tokens are emitted on **both `:host` and `:root`**. The extension renders
  inside a shadow root on pages we do not control, where `:root` is the host
  page's `<html>` and carries none of our tokens.
- Components are Web Components so the same element works in a content script's
  shadow root and on the Pages site, whatever the app is written in.
- Every component ships its own reset and adopts tokens via `adopt(root, …)`.
  Injected UI cannot assume the host page has sane `box-sizing` or margins, and
  must not inherit the host page's typography.
- Light is the default palette; dark is layered via `prefers-color-scheme` and
  `[data-theme]`. Never define a token only inside a media query.

Previews in `previews/` carry a first-line `<!-- @dsCard group="…" -->` marker
and are what syncs to the Claude Design project.
