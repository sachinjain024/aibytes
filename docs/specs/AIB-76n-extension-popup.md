# Spec: AIB-76n, module 3 `extension-popup`

Status: **draft, 22 Nov 2026, for review.** Module 3 of 6 in
`docs/specs/AIB-76n-capability-map.md`. Builds on `ledger-extension-ui` and
`app-core`. Design: A2, B1, D2 and the icon in
`docs/decisions/product/AIB-76n-extension-design.md`; copy from the
prototype's `copy.js` (`pop.*`).

## Objective

The extension itself, signed out: `apps/extension` (`@aibytes/extension`), a
Manifest V3 extension whose popup shows today's edition ranked, lets the reader
star rows and read gists, and shows their saved items. Loaded unpacked, it does
everything in the map's reader outcomes 1–4 except syncing to an account,
which `extension-auth` adds.

Who: aibytes.io readers who want the edition one click away in their toolbar.

Success looks like:

- Selecting the toolbar icon opens a 400px popup: `PopupHeader` with the
  edition's date, the saved toggle with its count, and Sign in; Ledger
  `ListRow`s in ranked order with the star under the source image (B1, E2 of
  AIB-75v); "That's the {date} edition." at the end; `PopupFooter` with
  "{date} · {count} items" and "View on Web".
- A star fills at once and survives closing the popup and restarting Chrome.
- The saved toggle shows every saved item, the same list `/saved` shows on
  aibytes.io, and toggles back to today.
- A row with a gist opens the gist in the popup, with "← Today" or "← Saved"
  at the top and the star, "Save"/"Saved" and "View on Web" at the bottom (D2).
  A row without one, or whose gist file is missing, opens its source in a new
  tab.
- Every link opens a new tab; the popup never navigates away from itself.
- On install, Chrome opens `https://aibytes.io/extension-onboarding` once.

### Not in this module

Sign-in, the account store, the merge, `externally_connectable`, the message
protocol (`extension-auth`). The onboarding page itself (`site-extension`). The
store submission (`store-listing`). Until `extension-auth`, Sign in opens the
onboarding page, which will not yet sign the extension in.

## The manifest

Generated by the build from `manifest.config.js`, so dev and store builds
differ only where they must:

```js
{
  manifest_version: 3,
  name: "aiBytes – AI News Feed for Developers",
  short_name: "aiBytes",
  description: "<the short description from store-listing; a placeholder until then>",
  version: pkg.version,
  key: "<the public key, map answer 5>",
  action: { default_popup: "popup.html", default_title: "aiBytes_", default_icon: { 16: …, 32: … } },
  icons: { 16: …, 32: …, 48: …, 128: … },   // Ledger's assets/extension PNGs
  background: { service_worker: "background.js", type: "module" },
  permissions: ["storage"],
}
```

- **`storage`** is the only permission (map assumption 2): signed-out saves
  live in `chrome.storage.local` so the background can merge them on sign-in.
  It shows no install warning.
- No `host_permissions`: `https://aibytes.io/content/*` sends
  `access-control-allow-origin: *` (checked live on 22 Nov 2026). Images load
  from their CDNs as `<img>`, which needs no permission.
- `externally_connectable` and `minimum_chrome_version` are added by
  `extension-auth`.
- The `key` makes an unpacked build's ID `faamldnehjdjdobapchedpmldfjjfife`, the
  store's.

## Data

All from `https://aibytes.io/content/` (a dev build can point elsewhere with
`VITE_CONTENT_URL`, e.g. `http://localhost:5173/content/`):

1. **Paint from the cache.** `localStorage["aibytes-extension-edition"]` holds
   `{ date, edition, cached_at }` for the last edition shown. Read
   synchronously, validated (an object, `schema_version === 1`, a real date, an
   `items` array), and rendered before any request. Anything else is treated as
   empty.
2. **Fetch.** `index.json`, then `editions[0]` (the newest; the index is
   sorted newest first) by its `path`. The HTTP cache (`max-age=600`) makes a
   reopen cheap. The fetched edition replaces the painted one and the cache.
3. **Refuse what we do not know.** `index.json`, an edition, `weekly/index.json`,
   a weekly issue and a gist each carry `schema_version`. Any value but `1`:
   that file is not used (the popup shows its error state, or for a gist opens
   the source), per `packages/feed-schema/feed.d.ts`.
4. **Today's list:** `rankedItems(edition.items)` over the whole file, hidden
   items included, then `inFeed`. Never filter first. The count is the visible
   list's length.
5. **Saved:** `filesToLoad`, then `savedGroups` and `leftOutNote` from
   `app-core/saved.js`, with `index.json` and `weekly/index.json` and only the
   files the saves name, exactly as `/saved` does. Sections are newest first,
   headed by their date or issue, ranked inside.
6. **A gist:** `gists/<slug>.json`. A 404, a parse failure or an unknown
   `schema_version` opens `item.url` in a new tab instead.

Fields read are only those in the contract (`feed.d.ts`); unknown fields are
ignored.

## Saves, signed out

`localSaves(storage, events)` from `app-core`, unchanged, over a small adapter:

```js
// chrome.storage.local, made to look like the synchronous Storage localSaves
// expects (spec AIB-76n extension-popup). load() fills a copy before the
// popup renders its stars; writes go through to chrome.storage.local, and
// changes from the background (the merge clears them) arrive as `storage` events.
export async function extensionStorage(chrome) { … return { storage, events }; }
```

A save's `from` is `{ edition_date }` for a row from today or a dated Saved
section, and `{ issue_slug }` for a weekly section, as on the site.

## The popup

- **Header** (`PopupHeader`): `midDate(edition.date)`; the saved toggle with
  `saves.length`; Sign in (`pop.signin`). Sign in calls
  `chrome.tabs.create({ url: "https://aibytes.io/extension-onboarding?step=signin" })`.
- **Rows:** `ListRow` with `starPos="visual"`, `onToggleSave`, and, when the
  item has `gist`, `gistHref` (the absolute gist URL) and `onOpenGist`.
- **End line** (`pop.end`) on Today only; **footer** (`pop.foot.meta`,
  `pop.site`) on both lists.
- **Empty Saved:** `pop.empty.title`, `pop.empty.body`. **Left out:** the
  `leftOutNote` line above the sections, as on `/saved`.
- **Gist view:** `PopupGistBar` (`pop.back.today` / `pop.back.saved`),
  `GistView as="panel"` with `appearanceHref` returning absolute aibytes.io
  URLs, `PopupActionBar` (`pop.gist.save` / `pop.gist.saved`, the site link).
  The scroll position of the list is kept for Back.
- **Links:** one click handler on the popup root: any `<a href>` to `http(s)`
  is opened with `chrome.tabs.create({ url })` and the default is prevented,
  so a link without `target` (a modified click on `gistHref`, an appearance
  link) cannot navigate the popup. `chrome.tabs.create` needs no permission.
- **"View on Web"** goes to `https://aibytes.io/<date>`, `/saved`, or
  `/gists/<slug>`, tagged by the site's link-tag rule
  (`docs/specs/AIB-145y-gist-analytics.md`: three tags, lower case):
  `utm_source=chrome-extension&utm_medium=extension&utm_campaign=` `today`,
  `saved` or `gist`. This module adds that row to the spec's table.
- **States** (copy approved 22 Nov 2026):
  loading with no cache, `pop.loading` "Loading today's edition…"; failed with
  no cache, `pop.error` "Couldn't load today's edition." and `pop.retry` "Try
  again"; failed with a cache, the cached list under `pop.stale` "Showing
  {date}. Couldn't check for a newer edition."; a refused `schema_version`,
  `pop.refused` "Update aiBytes_ to read this edition." (Chrome updates
  extensions itself; this should be rare).
- **Theme:** follows the OS, through Ledger's `prefers-color-scheme` tokens.
  No toggle in v1.
- **Fonts:** bundled. The build drops `styles.css`'s Google Fonts `@import` and
  adds `@font-face` rules for the packaged Inter (400, 500, 600, 700) and
  Bricolage Grotesque (500, 700, 800) `.woff2` files, both under the SIL Open
  Font License. No request leaves the extension for fonts.

## The background worker (this module's part)

```js
chrome.runtime.onInstalled.addListener(({ reason }) => {
  if (reason === "install") chrome.tabs.create({ url: ONBOARDING_URL });
});
```

`reason === "update"` opens nothing (map answer 4). `ONBOARDING_URL` is
`https://aibytes.io/extension-onboarding`, or the dev server's in a dev build.

Vite 7 and `@vitejs/plugin-react` 5 (as `apps/web`), React 18.3, Ledger,

## Code style

As `apps/web`: a header comment naming the spec; pure logic in its own file
with injected `fetch`, `storage` and `chrome` so `node --test` drives it.

```js
// The popup's edition (spec AIB-76n extension-popup): newest by index.json,
// refused unless schema_version is 1, ranked over the whole file, then inFeed.
export async function loadToday({ fetch, base }) {
  const index = known(await getJson(fetch, new URL("index.json", base)));
  const ref = index.editions[0];
  const edition = known(await getJson(fetch, new URL(ref.path, base)));
  return { edition, items: rankedItems(edition.items).filter(inFeed) };
}
```

## Testing strategy

- **`node --test`:** `content.js` (newest edition; refusal of `schema_version`
  2 for index, edition, weekly index, issue and gist; rank before `inFeed`
  against a fixture where filtering first would reorder; the cache's
  validation, with corrupt and missing entries), `links.js`,
  `extensionStorage.js` against a fake `chrome.storage` (load, write-through,
  an outside change raising a `storage` event), and the `onInstalled` handler
  (opens on `install`, not on `update`).
- **Built manifest:** a test reads `dist/manifest.json` from a production
  build and asserts the permission set is exactly `["storage"]`, there are no
  `host_permissions`, and the `key` is present.
- **By hand, and with Chrome DevTools for agents** (ticket item 2.4) once
  installed: load unpacked; check light and dark; star, close, reopen, restart
  Chrome; Saved against `/saved` with the same saves; a gist and Back; a row
  without a gist; every kind of link opens a tab; offline with and without a
  cache; a fresh install opens the onboarding URL and an update does not.

## Boundaries

- *Always:* contract fields only; refuse an unknown `schema_version`; rank, then
  filter; open links with `chrome.tabs.create`; feature-detect any Chrome API
  this module uses.
- *Ask first:* any permission beyond `storage`; any runtime dependency (the
  fonts are dev dependencies, copied at build); a change to a Ledger component
  (that goes in `ledger-extension-ui`).
- *Never:* load remote scripts or styles; import from `apps/web/src`; write to
  aibytes.io's storage or Firestore from this module; commit the zip.

## Success criteria

1. Loaded unpacked in Chrome stable, the extension's ID is
   `faamldnehjdjdobapchedpmldfjjfife`.
2. The popup paints the cached edition within 100 ms of opening (measured with
   `performance.now()` at the first render), then the fetched one.
3. Today's list equals aibytes.io's ranked feed for the same date, item for
   item.
4. The Saved list equals `/saved`'s for the same saves (the site's local saves
   copied into the extension by hand for the check).
5. A star persists across closing the popup and restarting Chrome.
6. The production manifest asks for `storage` only; Chrome's install dialog
   shows no permission warning.
7. A fresh install opens the onboarding URL once; an update opens nothing.
8. `npm test -w @aibytes/extension` passes.
